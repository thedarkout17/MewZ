# MewZ on iPhone

The iPhone app is the same MewZ: the same queue, Mix, libraries, album search and
lyrics rules (`shared/`), with screens laid out for a phone in portrait (`phone/`).
It's built on GitHub's Macs, so **you don't need a Mac** — just a Windows or Mac
computer for the one-time install, a cable, and a free Apple ID.

## 1. Get the app file (MewZ.ipa)

Every push to the `ios` branch (and `main` / `cleanup`) builds it automatically.

1. On GitHub, open the repo → **Releases** (right-hand side).
2. Open the draft release **ios-app** (drafts only show when you're signed in; they're
   private to you).
3. Download **MewZ.ipa**.

To build again without changing code: **Actions → Build → Run workflow**.

## 2. Install it

Apps from outside the App Store have to be signed with your Apple ID. Two free tools do
this; pick one.

### Sideloadly (simplest; Windows or Mac)
1. Install iTunes **from apple.com** (not the Microsoft Store) and iCloud, then
   [Sideloadly](https://sideloadly.io).
2. Plug in the iPhone, unlock it, tap **Trust**.
3. Drag `MewZ.ipa` into Sideloadly, enter your Apple ID, press **Start**.
4. On the iPhone: **Settings → General → VPN & Device Management** → your Apple ID →
   **Trust**.
5. iOS 16+: **Settings → Privacy & Security → Developer Mode → On** (the phone restarts).

### AltStore (re-signs itself over Wi-Fi)
Install AltServer on your computer and AltStore on the phone
([altstore.io](https://altstore.io)), then in AltStore: **My Apps → + → MewZ.ipa**.
AltStore renews the 7-day signature in the background while the computer is on the
same Wi-Fi.

**The 7-day limit:** with a free Apple ID, sideloaded apps stop opening after 7 days
until they're re-signed (re-install with Sideloadly, or let AltStore refresh it). Your
libraries, history and API key are kept. A paid Apple Developer account ($99/year)
makes it a year.

## 3. YouTube API key (for search)

Search uses the same YouTube Data API key as the headunit. Either:

- **Paste it in the app**: copy the key (it starts with `AIza`), search for anything,
  and tap **Paste API key** on the message that appears. It's saved on the phone; or
- **Build it in**: repo **Settings → Secrets and variables → Actions → New repository
  secret**, name `YOUTUBE_API_KEY`, value your key. The next build includes it.

If the key is restricted to **Android apps** in Google Cloud Console, the iPhone can't
use it. Either set its application restriction to **None** (keep the API restriction to
YouTube Data API v3), or make a second key restricted to **iOS apps** with the bundle id
`com.headunit.music.phone` (Sideloadly may change the bundle id; check it in the app
list).

## What's different from the headunit

- **Keyboard:** the iOS keyboard instead of the glass keyboard. Its 🎤 key does voice search.
- **Back:** swipe in from the left edge (closes the page on top, like the headunit's Back).
- **Now Playing:** portrait layout; swipe down, tap the handle or tap empty space to
  minimise. Lyrics replace the artwork.
- **Lock screen, Control Center, AirPods, Bluetooth and car controls** all work, with
  title, artist and artwork. Playback continues with the screen locked; the next song is
  buffered ahead so it follows on without a gap. Calls and Siri pause it, unplugging
  headphones or disconnecting Bluetooth pauses it.
- **CarPlay:** a sideloaded app can't show its own CarPlay screen (Apple only grants
  that to App Store apps), but MewZ appears in CarPlay's Now Playing, and the car's
  buttons work.
- **Audio:** found straight from the phone, using the same YouTube client NewPipe uses
  today (visionOS). If YouTube changes something and songs stop playing ("YouTube changed
  something"), the values in `phone/src/commonMain/.../data/InnerTube.kt` need updating
  to match NewPipeExtractor's `ClientsConstants.java`.

## For development

- `phone/` — the app's Kotlin: `data/` (YouTube, LRCLIB, saving), `player/` (queue logic +
  AVPlayer engine in `iosMain`), `ui/` (screens, ported from the headunit's).
- `iosApp/` — the Xcode wrapper (`project.yml`, generated by XcodeGen on CI).
- CI also renders the iPhone screens on Linux (`phone/src/desktopTest/ScreenshotTest.kt`) to
  the **ci-android** draft release, along with a headunit debug APK.
- On a Mac: `brew install xcodegen && cd iosApp && xcodegen && open MewZ.xcodeproj`, pick
  your team under Signing, and Run.
